Critical

Broken authorization leading to full account takeover

CVSS 9.8 Target: acme-corp.example Reported: Feb 2026
Resolved ›

Summary

The password-reset endpoint trusted a client-supplied user_id parameter instead of deriving identity from the active session, allowing any authenticated user to reset the password of any other account.

Steps to reproduce

  • Trigger a password reset for your own account and intercept the confirmation request.
  • Modify the user_id field to a victim's numeric ID.
  • Submit — the server accepts the new password without re-validating ownership.

Impact

Full account takeover for any user, including admin accounts, with no interaction required from the victim.

Remediation

Vendor now binds the reset action to the authenticated session and re-validates the reset token server-side. Fix shipped within 72 hours of report.

High

IDOR in internal API exposes private billing records

CVSS 8.1 Target: billing.example-saas.io Reported: Nov 2025
Resolved ›

Summary

The /api/v2/invoices/{id} endpoint returned full invoice data — including linked payment method metadata — for any sequential ID, regardless of the requesting user's organization.

Steps to reproduce

  • Authenticate as a low-privilege user and fetch your own invoice.
  • Increment the invoice ID and replay the request.
  • Observe invoices belonging to other tenants returned in full.

Impact

Cross-tenant exposure of billing data across the entire customer base — a mass horizontal privilege escalation.

Remediation

Object-level authorization checks added; invoice IDs additionally migrated to non-sequential identifiers.

Medium

Stored XSS via unsanitized profile display-name field

CVSS 6.4 Target: community.devtools.app Reported: Sep 2025
Resolved ›

Summary

The display-name field accepted raw HTML which was rendered unescaped on any page listing that user's activity, including moderator dashboards.

Steps to reproduce

  • Set display name to a script payload via the profile settings API.
  • Post any public comment.
  • Payload executes in the browser of anyone viewing the activity feed — including moderators with elevated session cookies.

Impact

Session hijacking risk against moderator and admin accounts viewing user-generated content.

Remediation

Output encoding enforced on all user-controlled display fields; CSP header tightened as defense in depth.

Low

Verbose error messages leak internal stack paths

CVSS 3.1 Target: api.startupname.io Reported: Jul 2025
Resolved ›

Summary

Malformed JSON payloads triggered unhandled exceptions that returned full stack traces, revealing internal file paths, framework version, and library names.

Impact

Information disclosure useful for fingerprinting the stack ahead of further attacks — low severity in isolation.

Remediation

Generic error responses now returned in production; detailed traces logged server-side only.
